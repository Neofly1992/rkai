# 分阶段实施与验收规格

状态：2026-10-05：用户已授权 M2 实现，非硬件实现与真实 CPU 证据已落地；M1 真机静态诊断后置，M2 真机验收未完成。逐项边界见 [M2-STATUS](M2-STATUS.md)，不以 mock/CPU 代替 NPU 证据。

## 里程碑划分

分为三个里程碑，每个都能独立演示与验收。划分依据是外部依赖与交付闭环，不按目录/框架分阶段；“基础设施写完”不单独算产品里程碑。

| 里程碑 | 完整交付 | 必须提供的证据 |
| --- | --- | --- |
| M1 模型获取与诊断 | uv 工程、release/debug、配置/日志、manifest 校验、registry 解析、HF/MS/镜像、SQLite、pull/本地导入/delete、doctor 静态检查 | 默认/显式来源一致且冲突报错；两公开源真实下载、latest 快照、断点恢复、摘要失败、共享引用、删除保护；两种 profile 日志与结果分离 |
| M2 转换与本地执行 | 受管转换环境、runtime/worker、convert/run、单次与连续交互、非 LLM 与 LLM 等不同能力、CPU fallback | 真 RK3588 完成非 LLM 转换/导入/推理；不同语义模型复用管理层；取消/父退出/卡死回收、资源准入；CPU 开关与错误边界、参考输出比较；异机转换记录完整 |
| M3 本地服务与首版交付 | FastAPI 协议范围、systemd、可安装 wheel、文档及完整验收 | 各协议合法/拒绝/流式/断连路径；大小边界和多模态媒体预算；安装卸载不改驱动；CLI/服务共享规则、三条完整用户流程 |

M2 内按小步完成 worker、转换和各类模型适配，不为每项设一个需要用户批准的里程碑。embedding/decision 等逐项记录真实支持结果；若明确范围受工具链阻塞，报告具体缺项，不能以“通用接口存在”宣称完成。

每个里程碑保持同一架构和正式质量标准，不把临时代码推到下一阶段清理。整体复杂度来自 SDK、进程、存储恢复和协议交互，三个里程碑比一次性大交付更容易定位问题。

这些不是“通用平台只支持两个模型”的上限。代表模型用于验证扩展机制，正式支持清单由精确模型 revision/目标/runtime/adapter 及验证证据构成。新适配不能要求每个模型重新实现 pull/convert/run/serve。

## 真实验证分类

- 结构检查：只证明 schema/引用规则，不能证明文件可下载。
- 源与存储集成：真实远端固定内容、真实 SQLite 重开与文件提交，不以 mock 代替。
- 转换：实际工具链成功生成、记录输入输出；异机不等于 NPU 验证。
- 硬件执行：加载、推理、取消、卸载及再次使用，记录板卡/内存/OS/驱动/runtime。
- 语义正确性：分类输出对应标签与参考排名；embedding 形状/有限值/相似度合理；decision 输出合法且对照参考；文本生成按协议和行为验证，不要求逐字一致。
- 用户验收：少量完整使用流程，由用户给出结论，不能从自动测试推导。

## 每阶段出口

该阶段承诺的行为与失败路径完成，文档同步，有可重复验证入口。缺设备/网络时如实保留未运行项，可继续无依赖工作，但不将阶段标为完成。性能数值只来自真实测量，不用理论 NPU TOPS 代替模型表现。

跨阶段都必须保护已有用户文件，不在测试中操作默认库。测试通过后不无理由反复扩大测试；问题修复增加有意义的回归，避免测试实现副本。
